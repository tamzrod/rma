# RMA-001 — Harden authoritative raw-memory core

Status: ARCHIVED — accepted 2026-11-21

## Closure record
All required gates executed and green on Go 1.25.14 in the isolated OpenHands workspace; evidence in `docs/verification/RMA-001.md`. Requirements below are preserved unchanged.

## Objective
Make the existing protocol-independent memory core safe for concurrent reads/writes and adversarial/invalid ranges without replacing its API.

## Authorized edits
- `internal/core/memory/{core.go,bank.go,build_from_specs.go,errors.go,bitops.go}` and new focused `*_test.go`.
- Task state, handoff, verification and archive records required by CWAL.
- No raw TCP adapter, listeners, authority, protocol-specific logic, runtime config, deployments or dependencies.

## Invariants
1. Core layout remains fixed after Seal; no new bank after sealing.
2. Read and write each operate atomically on the addressed bank, with no torn read, write, or data race.
3. Unknown MemoryID, invalid counts/ranges, overflows and malformed payloads return explicit errors rather than panics.
4. No partial mutation on rejected writes or failed bank construction; BuildFromSpecs has no partial publish.
5. Existing `ReadUnits`, `WriteUnits`, `BuildFromSpecs`, `Seal` interfaces stay compatible and bit-address semantics remain unchanged.
6. Bounded allocations and no unbounded requested-memory allocation or crash from arithmetic overflow.
7. Do not introduce protocol, RBE, policy, persistence or authentication logic into the core.
